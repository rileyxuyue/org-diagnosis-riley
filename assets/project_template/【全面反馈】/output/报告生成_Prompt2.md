# 任务

我要你基于已经完成的 Step1 结构化数据（step1_output.xlsx），为目标 BG（如 CSIG / S3 / WXG 等）生成 **360 评价结构化分析报告**（.md 格式）。

每份报告对应一个部门（dept_idx），包含该部门所有管理者的反馈分析。

---

## 输入数据

我会上传 `step1_output.xlsx`，它包含 4 个 sheet：

### Sheet 1: `部门概览`
列：dept_idx, dept_path, n_managers, total_items

### Sheet 2: `管理者小计`
列：dept_idx, mgr_name, mgr_role, bp_status, flash_count, more_count, bp_positive_items, bp_negative_items
- bp_status 取值：正常 / 点赞 / 待关注 / 空缺

### Sheet 3: `原文清单`
列：dept_idx, mgr_name, mgr_role, n_id, source, polarity, text, note
- source: 闪光点 / 更多期待 / bp观察
- polarity: 正向 / 待关注
- n_id: N01, N02, ...
- note: bp观察 的小项标签（如 "bp观察:小项-工作态度与责任心"）；或 "本人可见拆出" / "本人不可见拆出"

### Sheet 4: `异常日志`
列：dept_idx, mgr_name, issue_type, detail
- 用于报告说明段，标注全空管理者、bp异常等情况

4. 每批跑完后用 present_files 给我看

## 报告格式（严格遵守，所有部门一致）

报告结构按以下顺序：

### 1. 一级标题 + 部门信息

```
# {BG} / {dept_path} — 360评价结构化分析

**部门管理者数：N 人**（mgr1名 / mgr2名 / mgr3名）
```

### 2. TL;DR 表格

3-4 列表格：维度 | 判断 | 一句话总结
- 4-9 个维度，覆盖该部门所有 N# 条目（MECE），维度数严格按内容自然分，不要凑数也不要塞，可能是 4 维也可能是 10 维，看部门信号集中度
- 判断仅用三档：**共性优势** / **局部待关注** / **共性不足**
- 维度示例（依业务而定）：战略前瞻与AI布局、业务投入与一线深耕、跨部门协同、执行力与目标达成、团队管理与人才培养、管理沟通
- ⚠️ **不得包含健康维度**（身体健康/健康与可持续性/健康与工作节奏等不纳入报告）

### 3. 总体结论段（1 段 prose）

- 提炼共性优势 + 关键改进方向
- 必须点明每个 mgr 的 bp_status（空缺/正常/点赞/待关注）
- 异常处理需说明（如某 mgr 全空、bp 内容标记"无数据支持"等）

### 4. 第一步：原文清单

每个 mgr 一个三级标题：

```
### === 管理者：mgr_name(中文名)（mgr_role） ===
```

每个 N# 条目一行，**严格按以下格式（绝对必须 verbatim）**：

```
[N01 | 闪光点 | 正向] {text 全文}
```

格式细节：
- 方括号内三段式：N## | source | polarity，竖线两侧空格
- N## 不补零（N01 而非 N001）
- text 完整 verbatim，不删不改不缩略
- 同一条目内的多个 quoted text 用 `；`（全角分号 U+FF1B）连接
- bp 观察条目末尾不再附 note 字段（note 仅用于内部识别）
- 噪声文本（无/无。/NA/暂无/没有等）若已被 step1 过滤就不会出现；如出现按原文保留
- 前缀 "本人可见：" / "本人不可见：" 已在 step1 去除，无需处理

每个 mgr 末尾加一行 bp 状态注释：
- 若 bp_status=空缺：`> bp 观察：原 bp 段及所有小节均标记 "**空缺**"，无 bp 抽取条目。`
- 若 bp 有内容：`> 注：bp 观察"主要工作职责"段为中性工作描述，不抽取。`

每个 mgr 末尾必加小计行：

```
**小计**：正向声音 = X / 待关注声音 = Y / bp 观察：无 或 X 个声音
```

**声音数计算规则（重要，去重）**：
- 一条 N# 算 1 个声音，闪光点 / 更多期待 每条独立计 1 声音
- bp 观察的 N# 条目：**所有 bp+ 共算 1 个 bp 正向声音；所有 bp- 共算 1 个 bp 待关注声音**（不按条数累加）
- 例：某 mgr 闪光点 N18 + bp 正向 N25 + bp 正向 N26 → 正向声音 = **2**（peer 1 + bp 合计 1）
- 闪光点合计 = 正向声音中的 peer 部分；更多期待合计 = 待关注声音中的 peer 部分

### 5. 第二步：维度定义（MECE）

表格：维度 | 定义 | 覆盖条目
- 覆盖条目格式：`mgr1-N01/N03/bp N12, mgr2-N05(待)/N08`
- `(待)` 标记表示该条是待关注；不标记则是正向
- bp 来源的 N 编号必须前缀 `bp `（如 `bp N12`）
- 所有 N# 都必须被某个维度覆盖（MECE 原则）
- ⚠️ **不得设健康维度**

### 6. 第三步：分维度详情

每个维度一个三级标题：

```
### 维度一：{维度名}
> {一句话定义}

**判断：共性优势 / 局部待关注 / 共性不足**
```

#### 6.1 管理者行格式（必须严格遵守，唯一格式）

```
- **mgr_name(中文名)**：正向 X 声音 (N01, N02, bp N03) | 待关注 Y 声音 (N25, N28)
  - "正向引用原文"（N01）
  - "正向引用原文，过长时截取关键部分"（N02，节选）
  - bp："bp来源的正向引用"（bp N03，节选）
  - 待关注："待关注引用原文"（N25，节选）
  - 待关注："待关注引用原文"（N28）
```

##### 管理者统计行规则

- 格式：`正向 X 声音 (具体N编号列表) | 待关注 Y 声音 (具体N编号列表)`
- X / Y 为**去重后**的声音数（多条 bp 来源只算 1 人）
- 括号内必须列出**所有**对应的 N 编号，逗号分隔
- bp 来源标注为 `bp N27` 格式
- 如果只有正向没有待关注，省略 `| 待关注...` 部分；反之亦然
- ❌ **禁止**使用 `含 X bp正向` 等非标准格式
- ❌ **禁止**只写数量不列 N 编号
- ❌ **禁止**省略 N 编号列表

##### 引用行规则

- **正向引用行**：`  - "引用原文"（N编号）` 或 `  - "引用原文"（N编号，节选）`
- **bp 正向引用行**：`  - bp："引用原文"（bp N27，节选）`
- **待关注引用行**：`  - 待关注："引用原文"（N25）` 或 `  - 待关注："引用原文"（N25，节选）`
- **bp 待关注引用行**：`  - 待关注：bp："引用原文"（bp N30，节选）`
- 每条 N 编号对应的原文**独立一行**
- 同一 mgr 在一个维度的所有引用聚集在该 mgr 行下方

##### 引用原文处理

- **短原文**（≤80字）：verbatim 完整引用
- **长原文**（>80字）：截取最具代表性的关键语句，标注 `（N编号，节选）`
  - 截取时在语义完整处断开（句号、逗号）
  - 可用 `……` 表示省略中间部分
- **多条原文合并为一条 N#**（如 "1.xxx 2.xxx"）：取最具代表性的一条

##### 逐条引用要求（核心）

- 管理者行中标注的**每一个 N 编号**，下方都必须有对应的引用子列表行
- 不允许只选摘"代表性"的几条——**全部列出**
- 唯一允许省略引用行的情况：原文为纯礼貌/空洞内容（如"暂无""继续加油""已经很好了""都挺好"等），此类条目可不列引用行，但**仍需计入声音数并保留 N 编号**

##### 错误格式（绝对禁止）

```
❌ - **name**：正向 3 声音 | 含 1 bp正向 (N23/N27)
❌ - **name**: 正向 9 (N01-04/N06/N10) — "行内引用"（N11）
❌ - **name**：正向 5 声 | 待关注 3 声        （没有列出具体 N 编号）
❌ - **name**：通用正向 2 (N06/bp N30) / 通用待关注 7
❌ - **name**：正向 7 声                       （没有 N 编号列表）
```

#### 6.2 维度末尾整体判断

每个维度末尾加 1 行整体判断：

```
> **共性优势** — 一句话说明为什么是这个判断。
```

判断规则：
- **共性优势**：≥3 个 mgr 有正向反馈
- **局部待关注**：部分 mgr 有问题但不普遍
- **共性不足**：≥2 个 mgr 都有同向待关注反馈

### 7. 报告说明（最后一段）

```
## 报告说明

- 抽取条目总数：mgr1 X + mgr2 Y + ... = N 条
- 声音数：正向合计 X / 待关注合计 Y
- bp 观察处理：{对每个 mgr 的 bp_status 做说明}
- {特殊情况说明，如重复 mgr、异常日志等}
- "本人可见：" / "本人不可见：" 前缀已统一去除
```

## 关键约束（绝对不能违反）

1. **第一步原文清单中所有 N# 条目必须 verbatim 完整保留**，不能省略、缩略、合并、改写
2. **n_id 格式严格为 `[N## | source | polarity]`**，竖线两侧必须空格
3. **多条 quoted text 用全角分号 `；`（U+FF1B）连接**，不是半角
4. **dept_idx 重复 mgr** 处理：如某 mgr 出现在多个 dept，在第二个 dept 报告中第一步用引用方式（"反馈条目同 dept_X，详见 X_xxx.md"）但**仍需在本报告中完整列出所有 N#**，避免读者翻阅
5. **bp_status=空缺** 时该 mgr 无 bp 抽取条目；bp_status=正常/点赞/待关注 时按"做得好/做得不好"小标题切分
6. **维度 MECE**：覆盖条目时温和的"暂无/继续保持/都很好"类条目可被代表性条目覆盖，不必逐条列出，但小计声音数要包含
7. **判断三档严格使用**：共性优势 / 局部待关注 / 共性不足，不要发明新档位
8. **数据全空 mgr** 单独说明 "反馈数据全部缺失，无可抽取条目"
9. **bp 去重计数**：同一 mgr 所有 bp+ 在声音数中合并为 1，所有 bp- 合并为 1（详见 6.1）
10. **健康维度禁用**：身体健康/健康与可持续性/健康与工作节奏 整块不纳入报告（TL;DR、维度定义、详情三处都不出现）
11. **维度归属一致性**：第三步引用的 N 编号必须是第二步该维度覆盖列表中的条目，不能跨维度引用；正向/待关注极性必须与第一步一致
12. **不要在报告中暴露任何 PII 或敏感信息**之外的内容；保持原文风格

## 完整性自检清单（生成后自验）

生成报告后，请逐项打勾：

1. ☐ 第一步每个 N# 条目都 verbatim 列出，格式 `[N## | source | polarity] text`
2. ☐ 第一步每个 mgr 末尾有 bp 状态注释行 + 小计行
3. ☐ 小计的声音数已按 bp 去重规则计算（peer 累加 + bp+ 算 1 + bp- 算 1）
4. ☐ 第二步维度定义表 MECE，所有 N# 都被覆盖
5. ☐ 第三步每个 mgr 行的格式统一为 `正向 X 声音 (具体N编号列表) | 待关注 Y 声音 (具体N编号列表)`
6. ☐ 每个标注的 N 编号都有对应的引用子列表行（除纯礼貌内容外）
7. ☐ 正向引用行无前缀，待关注引用行以 `待关注：` 开头
8. ☐ bp 来源引用以 `bp：` 标注，N 编号格式为 `bp N27`
9. ☐ 长引用（>80字）已截取并标注 `（N编号，节选）`
10. ☐ 不存在健康维度（TL;DR、维度定义、详情三处都没有）
11. ☐ 第三步引用的 N 编号与第二步覆盖列表一致，未跨维度引用
